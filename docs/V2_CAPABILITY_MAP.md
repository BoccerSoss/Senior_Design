The workflow labels summarize the public page; the implementation and limits columns describe our own code. LINK's page includes unidentified valves among flagged closure candidates. V2 deliberately requires a confirmed eligible manual type before crediting a boundary. This difference is a conservative prototype design choice, not a statement of an industry or laboratory requirement. ## Project-specific spatial grid

The separate **Grid** tool is a project requirement. Its configurable rows and columns divide the actual sheet; each equipment symbol's center determines a one-based **(column,row)** cell. Coordinates appear below equipment in this view and export as JSON. Branches keep their locations in the same sheet grid, and different equipment may share a cell. Coordinates are qualified by sheet and component IDs.

Grid settings affect display/location references only. They do not create junctions, change adjacency, redirect arrows, alter valve credit or change an isolation search. Piping topology is stored as explicit component-to-component connections. See [grid code](../src/aip/v2/grid.py), [grid/storage tests](../tests/test_v2_store_grid.py) and [network tests](../tests/test_v2_network.py).

## Verification and next acceptance steps

The generated two-sheet example exercises branches, a confirmed continuation, normally closed/manual/check valves, instruments and deliberate unbounded special paths. Its known graph demonstrates software behavior; it does not measure automatic interpretation accuracy. Local tests cover grid independence, correction persistence, graph scoping, malformed/missing links, isolation rules, imports, HTTP boundaries and mocked provider responses. [Tests](../tests/)

Before expanding this into an institutional tool, agree the grid convention and equipment/junction semantics with the project reviewer, establish site-specific isolation rules, evaluate extraction on held-out permitted drawings, test an approved image-capable endpoint if desired, and design authenticated access/deployment with the institution. The present candidate result is not an approved clearance or authority to operate equipment.

The app reads provider credentials from its process environment; it does not reuse an ORNL ChatGPT sign-in or assume API entitlement. An authorized API organization/gateway and its applicable permissions are a separate setup step. OpenAI documents separate ChatGPT and API billing systems. [OpenAI billing guidance](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)

For launch, demonstrations, grid details, corrections and configuration, see the [V2 workbench guide](V2_WORKBENCH.md).
